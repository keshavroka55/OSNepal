# Contributing to Open Source Nepal (OSNepal)

First of all, thank you for your interest in contributing to Open Source Nepal!

OSNepal is a community-driven platform built to bring Nepal's developers, students, designers, founders, and investors together to create meaningful projects.

We welcome contributions that improve the platform, fix bugs, introduce new features, improve documentation, or enhance the developer experience.

## 1. Getting Started

Before contributing:

1. Fork the repository.
2. Clone your fork.
3. Create a new branch for your changes.
4. Install dependencies and configure the environment.
5. Run the application locally.
6. Test your changes before submitting a pull request.

## 2. Development Guidelines

Please follow these guidelines:

- Write clean, readable, and maintainable code.
- Follow the existing project architecture and coding conventions.
- Use meaningful variable, function, and component names.
- Avoid unnecessary dependencies.
- Validate API inputs and handle errors properly.
- Do not commit secrets, credentials, or environment files.
- Add or update tests when introducing new functionality.
- Update documentation when necessary.

## 3. Branch Naming

Use descriptive branch names:

- `feature/add-project-filter`
- `fix/authentication-error`
- `docs/update-api-reference`
- `refactor/project-service`

## 4. Commit Messages

Use clear and meaningful commit messages.

Examples:

- `feat: add project discovery filters`
- `fix: resolve authentication issue`
- `docs: update installation guide`
- `refactor: improve project service`

## 5. Pull Request Guidelines

Before submitting a pull request:

- Make sure your code builds successfully.
- Run backend tests.
- Run frontend type checks.
- Run the production build check.
- Describe what you changed and why.
- Include screenshots for significant UI changes.
- Reference related issues when applicable.

Pull requests should be focused on a specific improvement.

## 6. Project Attribution and Branding

Open Source Nepal (OSNepal) is the original project.

If you fork, modify, redistribute, or build a derivative version of this project, you must preserve appropriate attribution to the original project.

The following attribution requirements apply:

### Required Attribution

- Preserve the original copyright and license notices.
- Include a clear reference to the original project in your README.
- Include a link to the original Open Source Nepal repository.
- Do not claim that the original OSNepal project or its development is your original work.

### Logo and Brand Attribution

When distributing a modified or derivative version of OSNepal as a publicly accessible application, you must prominently display the original OSNepal logo and attribution.

The attribution must:

- Be visible on the application's landing page, homepage, or main application interface.
- Use the official OSNepal logo without misleading modifications.
- Clearly identify Open Source Nepal as the original project.
- Include a clickable link to the original project repository or official website.

Recommended attribution:

"Powered by Open Source Nepal (OSNepal)"

Original Repository: https://github.com/keshavroka55/OSNepal (might be change later in the future)

Original Website: https://osnepal.vercel.app

The original OSNepal branding must not be removed or hidden in publicly distributed derivative applications.

### Independent Branding

You may customize the application's name, colors, layout, and other design elements.

However, customization does not remove the requirement to acknowledge the original project.

You must not present a derivative project as the official Open Source Nepal platform.

## 7. Code of Conduct

Contributors are expected to:

- Be respectful and professional.
- Welcome developers of all experience levels.
- Provide constructive feedback.
- Avoid harassment, discrimination, and abusive behavior.
- Help maintain an inclusive open-source community.

If you have questions, suggestions, or ideas, open a GitHub issue or start a discussion in the repository.
